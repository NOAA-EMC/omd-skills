# Modern Target-Based CMake

Directory-level commands propagate to whatever happens to be defined below
them, in file-processing order, which is why large scientific builds become
undebuggable. Usage requirements belong on targets.

## Project skeleton

```cmake
cmake_minimum_required(VERSION 3.23)
project( mom6
         VERSION 1.14.0
         LANGUAGES C CXX Fortran )

list( APPEND CMAKE_MODULE_PATH "${CMAKE_CURRENT_SOURCE_DIR}/cmake" )

set( CMAKE_Fortran_MODULE_DIRECTORY ${CMAKE_CURRENT_BINARY_DIR}/mod )
```

Rules:

- `project()` before anything that needs a compiler; `LANGUAGES` lists only
  what is actually compiled (`Fortran` pulls in a C compiler implicitly on
  many toolchains, which breaks Cray mixes if `C` is not enabled deliberately).
- Put the module directory on the *binary* tree, never the source tree.
- Never call `enable_language( X )` conditionally inside a target definition;
  enable languages at the top and let `try_compile` decide support.

## Libraries

```cmake
add_library( mom6::physics STATIC ${MOM6_PHYSICS_SOURCES} )

target_include_directories( mom6::physics
  PUBLIC  $<BUILD_INTERFACE:${CMAKE_CURRENT_BINARY_DIR}/mod>
          $<INSTALL_INTERFACE:include>
  PRIVATE ${CMAKE_CURRENT_SOURCE_DIR}/src )

target_link_libraries( mom6::physics
  PUBLIC mpi::mpi fms2::fms2
  PRIVATE netCDF::netcdff )

target_compile_features( mom6::physics PRIVATE Fortran_FREE )
add_library( mom6::physics ALIAS mom6_physics )
```

- **Namespaced `ALIAS` targets** (`mom6::physics`) are what consumers link
  against. If it links, it can carry a namespace; using bare names lets a
  typo silently resolve to a linker flag.
- **`PUBLIC` = part of the interface** (headers, modules, and any dependency
  whose symbols appear in your inline code or `.mod` files). Fortran module
  dependencies are almost always `PUBLIC`, because a consumer that `USE`s your
  module needs *your* `.mod` directory on its include path and your dependency
  at link time.
- **`PRIVATE` = implementation only.** Correct for a `.c` file that happens to
  call NetCDF but exposes nothing of it.
- **`INTERFACE`** for header-only or module-only collections; `INTERFACE`
  targets may not have `SOURCES` attached directly.
- Never `link_directories()` to rescue a link; fix the imported target's
  `IMPORTED_LOCATION` instead.

## Executables

```cmake
add_executable( mom6 driver/mom6.F90 )
target_link_libraries( mom6 PRIVATE mom6::physics )
set_target_properties( mom6 PROPERTIES
  RUNTIME_OUTPUT_DIRECTORY ${CMAKE_BINARY_DIR}/bin )
```

- Do not link an executable against a library it does not use just to force
  static-archive member extraction; use `$<LINK_ONLY:...>` or whole-archive
  generator expressions instead of reordering `target_link_libraries`.
- Object libraries (`add_library( ... OBJECT )`) propagate usage requirements
  to consumers, but their objects must be referenced with
  `$<TARGET_OBJECTS:name>` *or* linked as the target itself — pick one, mixing
  both duplicates symbols.

## Install and export

```cmake
include( GNUInstallDirs )
install( TARGETS mom6 physics EXPORT MOM6Targets
         RUNTIME DESTINATION ${CMAKE_INSTALL_BINDIR}
         LIBRARY DESTINATION ${CMAKE_INSTALL_LIBDIR}
         ARCHIVE DESTINATION ${CMAKE_INSTALL_LIBDIR} )
install( DIRECTORY ${CMAKE_Fortran_MODULE_DIRECTORY}/
         DESTINATION ${CMAKE_INSTALL_INCLUDEDIR}/mom6/module )
install( EXPORT MOM6Targets NAMESPACE mom6:: DESTINATION ${CMAKE_INSTALL_LIBDIR}/cmake/MOM6 )
install( FILES ${CMAKE_CURRENT_SOURCE_DIR}/cmake/MOM6Config.cmake.in ... ) # generated by configure_package_config_file
```

- Module directories are installed explicitly: a Fortran consumer needs the
  `.mod` files, and CMake's `INSTALL_INTERFACE` include handling does not know
  about them.
- Use `configure_package_config_file` + `write_basic_package_version_file`
  rather than hand-written `Config.cmake`, so `find_package(MOM6 1.14)` version
  checks behave.

## Provenance and versioning

Components built with `ecbuild` write a version/branch stamp into the build
(`ecbuild_git_version_info`) instead of hand-maintained `VERSION.h`; when
reviewing a version bump, check that the changelog and the `project(VERSION)`
argument move together, because downstream `find_package` version checks read
the latter.
